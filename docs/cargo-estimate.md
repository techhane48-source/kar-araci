## Three-stage lifecycle (schema 6)
Pre-shipment declared single-unit desi takes priority; after Shipped/Delivered/AtCollectionPoint/UnDelivered/Returned, only positive API cargoDeci is used for a standard carrier forecast. The order-date tariff is the provisional effective-date convention, not verified shipping-date billing. First pre-shipment quote is retained separately; older rows without a recorded first quote remain unknown. Latest quote is replaced on successful non-older order updates, including same-carrier desi changes and changed carriers. Missing new quote clears current estimate rather than retaining obsolete cost; shipped orders cannot fall back to catalog manual cargo. Invoice totals still take priority when supported and tax basis reconciles; billed desi reported separately. No multi-package allocation. Reference: https://developers.trendyol.com/docs/sipari%C5%9F-paketlerini-ak%C4%B1%C5%9F-ile-%C3%A7ekme (cargoDeci may change, seller agreement whoPays=1). Changes that do not appear in the API modified-date stream are not guaranteed to arrive immediately; live verification required. Full primary tariff and refresh remain outstanding.

## Repricing without a new marketplace observation (schema 7)
Store the non-PII quote context separately from the computed amount, even if no tariff is installed or matches. Context includes observed carrier, chosen desi, order date, order amount, original-package eligibility candidate, observation source and modification timestamp. At report read time, recompute from the installed historical table for the recorded order day; use indexed carrier/desi rows. A tariff correction can update all selected reports without API requests or a new order modification. The original pre-shipment estimate and stored observation are not mutated. If the tariff is removed or the input conflicts, withhold the new estimate rather than keep a stale number. Invoice precedence and VAT reconciliation remain in effect. Legacy rows without context need another successful order sync before repricing is supported. This mechanism consumes locally installed dated tables, not a live official tariff feed. Tests use synthetic rates, no live marketplace writes.
