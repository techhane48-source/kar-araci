# Automatic read-only synchronization

A single host-managed cron worker selects due jobs across connected non-demo Trendyol accounts, using persisted attempt/success state. Default intervals: orders 15m, claims 30m, products 60m, settlements/documents/recent payout page 6h. No per-user scheduling action needed. The first financial/order/claim query targets 30 days; regular finance/claims queries overlap 7 days minimum, with a bounded outage recovery window. Existing sync range reports identify gaps; old data outside supported windows remains a manual backfill/support case. Failed/interrupted jobs retry after a minimum 15 minutes, a global nonblocking file lock prevents simultaneous workers, per-store locks protect sync calls. Six admissions per run and a 240-second admission budget (not a hard job timeout). One worker may be inadequate at high concurrency; benchmark and tune on actual hosting. Heartbeat reports actual invocation, not a guarantee each job succeeded.

Only the latest payment order page is refreshed automatically; historical pages and exact payout detail checks remain manual. No purchase costs, physical condition, banking or campaign file data is invented. No price changes or claim decisions. Cron must be configured once by administrator after live validation; no deployment or live invocation was performed in development. See DEPLOY.md.
